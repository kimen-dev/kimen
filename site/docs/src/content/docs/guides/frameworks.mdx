title: Framework integration
description: Using Kimen components in React, Vue, Angular and plain HTML, directly or through the generated @kimen/react, @kimen/vue and @kimen/angular wrappers.
---

Kimen components are standard custom elements, so they work in React, Vue,
Angular — and no framework at all — **without wrappers**. For the three
frameworks there are also generated wrappers on npm, `@kimen/react`,
`@kimen/vue` and `@kimen/angular`: typed props, typed event bindings, and
the framework form idiom (controlled props / `v-model` / value accessors).
Both paths are supported; wrappers add typing and idiom, never a
requirement.

## Generated wrappers

The wrappers are generated from the same component contract as the
elements and released with them, at the same version. Each one depends on
that exact version of `@kimen/elements`, so you install the wrapper and the
token stylesheets; the framework is a peer dependency. Importing a
component from a wrapper registers that element, and modules you never
import are tree-shaken away. Rendering is client-side, as with the elements
themselves.

### React wrapper

```sh
npm install @kimen/react @kimen/tokens
```

Peers: `react` and `react-dom` `^18 || ^19`. TypeScript needs
`moduleResolution` set to `bundler` or `nodenext`.

```tsx
import { useState } from 'react';
import { KiButton, KiInput } from '@kimen/react';
import '@kimen/tokens/css/core';
import '@kimen/tokens/css/ki-button';
import '@kimen/tokens/css/ki-input';
import '@kimen/tokens/css/base';

export function NameForm({ onSave }: { onSave: (name: string) => void }) {
  const [name, setName] = useState('');
  return (
    <>
      <KiInput
        label="Name"
        value={name}
        onInput={(event) => setName((event.target as HTMLKiInputElement).value)}
      />
      <KiButton variant="primary" onClick={() => onSave(name)}>
        Save
      </KiButton>
    </>
  );
}
```

Form components keep `value` and `checked` live and re-dispatch the native
`input` and `change` events, so React's own `onInput` and `onChange` work
as on native inputs. `ki-*` events are typed props: `onKiDismiss`,
`onKiClose`, `onKiChange`. The modules carry `'use client'`, so in a server
component tree (the Next.js App Router) they render as client components.

### Vue wrapper

```sh
npm install @kimen/vue @kimen/tokens
```

Peers: `vue` `>=3.4.38`; `vue-router` `>=4.5.0` is optional.

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { KiButton, KiInput, KiSwitch } from '@kimen/vue';
import '@kimen/tokens/css/core';
import '@kimen/tokens/css/ki-button';
import '@kimen/tokens/css/ki-input';
import '@kimen/tokens/css/ki-switch';
import '@kimen/tokens/css/base';

const name = ref('');
const notify = ref(false);
const save = () => console.log(name.value, notify.value);
</script>

<template>
  <KiInput label="Name" v-model="name" />
  <KiSwitch v-model="notify">Email notifications</KiSwitch>
  <KiButton variant="primary" @click="save">Save</KiButton>
</template>
```

`v-model` binds `value` on `input` for `ki-input` and `ki-textarea`,
`checked` on `change` for `ki-checkbox` and `ki-switch`, and `value` on
`change` for `ki-select` and `ki-radio-group`. The wrappers are Vue
components, so the `isCustomElement` setting below is not needed.

### Angular wrapper

```sh
npm install @kimen/angular @kimen/tokens
```

Peers: `@angular/core` and `@angular/forms` `^22.0.0`, and `rxjs`
`^7.8.0`. The package is built in the Angular Package Format.

```ts
import { Component } from '@angular/core';
import { FormControl, ReactiveFormsModule } from '@angular/forms';
import {
  BooleanValueAccessor,
  KiButton,
  KiCheckbox,
  KiInput,
  TextValueAccessor,
} from '@kimen/angular';

@Component({
  selector: 'app-settings',
  standalone: true,
  imports: [ReactiveFormsModule, KiButton, KiCheckbox, KiInput, BooleanValueAccessor, TextValueAccessor],
  template: `
    <ki-input label="Name" [formControl]="name"></ki-input>
    <ki-checkbox [formControl]="notify">Email notifications</ki-checkbox>
    <ki-button variant="primary" (click)="save()">Save</ki-button>
  `,
})
export class SettingsComponent {
  name = new FormControl('');
  notify = new FormControl(false, { nonNullable: true });

  save(): void {
    console.log(this.name.value, this.notify.value);
  }
}
```

The value accessors connect the form components to template-driven and
reactive forms: `TextValueAccessor` for `ki-input` and `ki-textarea`,
`BooleanValueAccessor` for `ki-checkbox` and `ki-switch`,
`SelectValueAccessor` for `ki-select` and `ki-radio-group`. Import them
next to the components they bind. `ki-*` events bind by their DOM name,
`(ki-dismiss)="onDismiss($event)"`, and `$event` is typed under
`strictTemplates`. The components use `OnPush`: in a zoneless app, update
state from event handlers with signals or `markForCheck`. Load the token
stylesheets globally, for example via `angular.json`: the core, one sheet
per `ki-*` tag the app uses, and the page contract.

```json
"styles": [
  "src/styles.css",
  "node_modules/@kimen/tokens/dist/css/core.css",
  "node_modules/@kimen/tokens/dist/css/ki-button.css",
  "node_modules/@kimen/tokens/dist/css/ki-checkbox.css",
  "node_modules/@kimen/tokens/dist/css/ki-input.css",
  "node_modules/@kimen/tokens/dist/css/base.css"
]
```

## Without wrappers

Install `@kimen/elements` and `@kimen/tokens`
([Getting started](/docs/getting-started/)). Every setup is then the same
two steps, regardless of framework: register the element, and load the token
core with the token sheet of each tag you use.

```ts
import { defineCustomElement as defineKiButton } from '@kimen/elements/ki-button';
import '@kimen/tokens/css/core';
import '@kimen/tokens/css/ki-button';

defineKiButton();
```

Register each element you use from its subpath (tree-shakable; internally
nested Kimen elements are defined recursively), or start the loader to define
tags as they appear:

```ts
import { defineCustomElements } from '@kimen/elements/loader';

defineCustomElements();
```

When a framework renders into its own shadow root, pass that root to
`observeRoot(root)` from the loader. Append the element before waiting for
`customElements.whenDefined(tag)` if you need to call its methods.

The token sheets still follow the tags your markup writes. A page that
cannot list them in advance loads the full sheet, `@kimen/tokens/css`, in
place of the core and the tag sheets: every token in one stylesheet.

Registration is client-side: on server-rendered pages the `ki-*` tags render
as plain markup and upgrade in the browser once the registration code runs.

## Two kinds of events, one rule

- **Re-dispatched native events** — native `input` events are composed and
  cross the shadow boundary on their own; native `change` is not, so every
  Kimen form control (`ki-input`, `ki-textarea`, `ki-select`, `ki-checkbox`,
  `ki-radio-group`, `ki-switch`) re-dispatches it as a composed event at the
  host. Listen for plain `change`/`input` exactly as on native controls.
- **`ki-*` CustomEvents** — component notifications with a typed `detail`:
  `ki-change` on `ki-tabs` (`detail.value`), `ki-close` on `ki-dialog`
  (`detail.reason`: `'method' | 'escape' | 'backdrop'`), and `ki-dismiss` on
  `ki-alert` (`detail` is `null`).

Both kinds are ordinary DOM events, so `addEventListener` always works —
that is the whole framework contract:

```ts
const tabs = document.querySelector('ki-tabs');

tabs?.addEventListener('ki-change', (event) => {
  console.log((event as CustomEvent<{ value: string }>).detail.value);
});
```

## React 19

React 19 supports custom elements out of the box: props that match a
property on the element instance are assigned as properties, everything else
becomes an attribute. Events bind declaratively with `on` + the literal
event name — **casing and dashes preserved** — so `onki-dismiss` listens for
`ki-dismiss`. React 18 sets every prop on a custom element as an attribute
and does not bind custom events from props: on React 18, use
[`@kimen/react`](#react-wrapper).

```tsx
// main.tsx — register once, at the entry point
import { defineCustomElement as defineKiAlert } from '@kimen/elements/ki-alert';
import '@kimen/tokens/css/core';
import '@kimen/tokens/css/ki-alert';

defineKiAlert();
```

```tsx
// App.tsx
export function App() {
  return (
    <ki-alert tone="warning" dismissible onki-dismiss={() => console.log('acknowledged')}>
      Your session expires in five minutes.
    </ki-alert>
  );
}
```

TypeScript does not know `ki-*` tags until you declare them. The element
interfaces exported from each subpath carry the prop types, so a small
augmentation gives you typed JSX (the generated `custom-elements.json`
manifest is the machine-readable contract if you prefer to generate these):

```tsx
// ki-elements.d.ts
import type { DetailedHTMLProps, HTMLAttributes } from 'react';
import type { KiAlert } from '@kimen/elements/ki-alert';

declare module 'react' {
  namespace JSX {
    interface IntrinsicElements {
      'ki-alert': DetailedHTMLProps<HTMLAttributes<KiAlert>, KiAlert> & {
        tone?: KiAlert['tone'];
        dismissible?: boolean;
        'dismiss-label'?: string;
        'onki-dismiss'?: (event: CustomEvent<null>) => void;
      };
    }
  }
}
```

## Vue 3

Tell the template compiler that `ki-*` tags are custom elements so it
neither warns nor tries to resolve them as Vue components:

```ts
// vite.config.ts
import vue from '@vitejs/plugin-vue';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    vue({
      template: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith('ki-'),
        },
      },
    }),
  ],
});
```

(Apps using the runtime compiler set the same predicate on
`app.config.compilerOptions.isCustomElement`.)

Then bind props with `:` and listen with `@` — `@change` hears the composed
native event, and `ki-*` events bind the same way (`@ki-close`,
`@ki-change`):

```vue
<script setup lang="ts">
import { ref } from 'vue';
import type { KiInput } from '@kimen/elements/ki-input';
import { defineCustomElement as defineKiInput } from '@kimen/elements/ki-input';
import '@kimen/tokens/css/core';
import '@kimen/tokens/css/ki-input';

defineKiInput();

const email = ref('');
const onChange = (event: Event) => {
  email.value = (event.target as KiInput).value;
};
</script>

<template>
  <ki-input label="Work email" type="email" :value="email" @change="onChange" />
</template>
```

## Angular

Add `CUSTOM_ELEMENTS_SCHEMA` so the compiler accepts non-Angular tags, bind
properties with `[...]` and events with `(...)` — Angular attaches them with
`addEventListener`, so `(change)` and `(ki-close)` both work as-is:

```ts
// main.ts — register once, at the entry point
import { defineCustomElement as defineKiSwitch } from '@kimen/elements/ki-switch';

defineKiSwitch();
```

```ts
// notifications.component.ts
import { Component, CUSTOM_ELEMENTS_SCHEMA } from '@angular/core';
import type { KiSwitch } from '@kimen/elements/ki-switch';

@Component({
  selector: 'app-notifications',
  standalone: true,
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
  template: `
    <ki-switch [checked]="enabled" (change)="onChange($event)">Email notifications</ki-switch>
  `,
})
export class NotificationsComponent {
  enabled = true;

  onChange(event: Event): void {
    this.enabled = (event.target as KiSwitch).checked;
  }
}
```

Load the token stylesheets globally, for example via `angular.json`:

```json
"styles": [
  "src/styles.css",
  "node_modules/@kimen/tokens/dist/css/core.css",
  "node_modules/@kimen/tokens/dist/css/ki-switch.css"
]
```

## Native form participation — no bindings required

Kimen form controls are form-associated custom elements
(`ElementInternals`): they contribute `name`/`value` to their owning
`<form>`, run native constraint validation (`required`), follow
`form.reset()` and appear in `FormData` — exactly like native inputs.
Because this is the platform, it behaves identically in React, Vue, Angular
and plain HTML; you do not need framework form bindings for submission:

```html
<form id="signup">
  <ki-input label="Work email" name="email" type="email" required></ki-input>
  <ki-checkbox name="tos" required>I accept the terms</ki-checkbox>
  <ki-button variant="primary">Create account</ki-button>
</form>

<script type="module">
  document.querySelector('#signup').addEventListener('submit', (event) => {
    event.preventDefault();
    console.log(Object.fromEntries(new FormData(event.target)));
  });
</script>
```

(`ki-button` submits by default — its `type` is `submit`, matching the
native button; cancel submissions from the form's `submit` event, not from
`click`.)
