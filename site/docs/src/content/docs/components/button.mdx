## Examples

### Variants

Onmars uses four visual roles. `secondary` is the default.

| Variant | Role |
| --- | --- |
| `primary` | Filled button for the main action |
| `secondary` | Outlined surface for supporting actions |
| `quaternary` | Neutral text for quiet actions |
| `ghost` | Accent text for actions that need a little more emphasis |

<Demo
  code={`<ki-button variant="primary">Primary</ki-button>
<ki-button variant="secondary">Secondary</ki-button>
<ki-button variant="quaternary">Quaternary</ki-button>
<ki-button variant="ghost">Ghost</ki-button>`}
/>

`tertiary` is deprecated. Use `secondary` for new buttons. Existing
`tertiary` buttons share the `secondary` appearance in onmars and keep
their legacy appearance in Material 3. Development builds warn when
the deprecated variant is used.

### Tones

`tone` carries intent (confirming, destructive) independently of hierarchy —
never use it for visual emphasis.

<Demo
  code={`<ki-button variant="primary" tone="neutral">Neutral</ki-button>
<ki-button variant="primary" tone="success">Success</ki-button>
<ki-button variant="primary" tone="danger">Danger</ki-button>`}
/>

### Slots and states

Decorative slotted media carries `aria-hidden="true"`; the slotted text is the
accessible name.

<Demo
  code={`<ki-button variant="secondary">
  <span slot="start" aria-hidden="true">New</span>
  With slots
</ki-button>
<ki-button variant="primary" disabled>Disabled</ki-button>`}
/>

### Form participation

`ki-button` defaults to `type="submit"`, exactly like a native button: it
submits the owning form, runs constraint validation and contributes
`name`/`value` to the form data. Cancel a submission from the form's
`submit` event, not from `click`.

<Demo
  layout="block"
  code={`<form onsubmit="event.preventDefault()">
  <ki-button name="intent" value="save">Save draft</ki-button>
</form>`}
/>

### Open a dialog

Set `commandfor` to the ID of a [ki-dialog](/docs/components/dialog/) in the
same document or shadow root. `command="show-modal"` opens it. A configured
dialog command takes precedence over form submission or reset.

<Demo
  code={`<ki-button commandfor="draft-preview" command="show-modal">Preview draft</ki-button>
<ki-dialog id="draft-preview" heading="Draft preview">
  <p>This draft is visible only to you.</p>
  <ki-button slot="footer" commandfor="draft-preview" command="close">Done</ki-button>
</ki-dialog>`}
/>

## Accessibility

The slotted text is the accessible name — icon-only usage is unsupported
(that is [ki-icon-button](/docs/components/icon-button/)'s job, with
its mandatory `label`). `disabled` removes the button from keyboard reach
and exposes the unavailable state through the internal native button; do not
use it for pending or loading semantics.
