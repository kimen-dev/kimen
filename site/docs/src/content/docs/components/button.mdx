## Examples

### Variants

`secondary` is the default.

| Variant | Role |
| --- | --- |
| `primary` | Filled button for the main action |
| `secondary` | Outlined surface for supporting actions |
| `quaternary` | Neutral text for quiet actions |
| `ghost` | Accent text for actions that need a little more emphasis |
| `outline` | Outlined surface with a filled selected state in toggle mode |

<Demo
  code={`<ki-button variant="primary">Primary</ki-button>
<ki-button variant="secondary">Secondary</ki-button>
<ki-button variant="quaternary">Quaternary</ki-button>
<ki-button variant="ghost">Ghost</ki-button>
<ki-button variant="outline">Outline</ki-button>`}
/>

`tertiary` is deprecated. Use `secondary` for new buttons. Existing
`tertiary` buttons share the `secondary` appearance in onmars and keep
their legacy appearance in Material 3. Development builds warn when
the deprecated variant is used.

### Tones

`tone` carries intent such as confirming or destructive in the momentary
primary, secondary, quaternary and ghost variants.

<Demo
  code={`<ki-button variant="primary" tone="neutral">Neutral</ki-button>
<ki-button variant="primary" tone="success">Success</ki-button>
<ki-button variant="primary" tone="danger">Danger</ki-button>`}
/>

### Toggle mode

Add `toggle` for an action such as Pin or Bold that stays selected until the
next activation. Set `selected` to start in the pressed state. Toggle colours
follow the variant and selection state.

<Demo code={`<ki-button variant="outline" toggle selected>Pin</ki-button>`} />

User activation emits a bubbling `ki-change` event with `{ selected }`.
Programmatic updates to `selected` are silent. Keep the visible label the
same in both states so assistive technology announces the state under the
same name.

Enabled outline actions use `--ki-button-outline-hover-bg`,
`--ki-button-outline-hover-fg` and `--ki-button-outline-hover-border` on hover.
Unselected filled and quiet toggles use `--ki-button-toggle-unselected-hover-overlay`.
A selected toggle keeps its fill on hover. Use `--ki-button-outline-selected-border`
to set the selected outline edge.

### Link mode

Set `href` for a call to action that navigates. The button renders a native
link with the same `button` part, so variants, sizes and tokens style it
like the button. Enter follows it and Space does not, as on any link.
`target`, `rel` and `download` pass to the link; `target="_blank"` without
`rel` gets `rel="noreferrer noopener"`.

<Demo code={`<ki-button variant="primary" href="#link-mode">Get started</ki-button>`} />

A link never submits or resets a form: `type`, `name`, `value`, `toggle`
and dialog commands do nothing while `href` is set. A disabled link drops
its destination and leaves the Tab order, like a disabled button.

### Content alignment

`--ki-button-justify-content` places the content along the button and
`--ki-button-text-align` aligns the lines of a multi-line label. Both are
`center` by default. Set both to `start` for a start-aligned choice.
`--ki-button-inline-size` defaults to `fit-content`. Use `100%` to fill
the containing block in button or link mode.

```html
<style>
  .choice {
    --ki-button-inline-size: 100%;
    --ki-button-justify-content: start;
    --ki-button-text-align: start;
  }
</style>
<ki-button class="choice" variant="outline" toggle>
  <strong>Starter</strong><br />One agent, one repository
</ki-button>
```

### Slots and states

The `start` and `end` slots each take one decorative icon. The
`--ki-button-{size}-icon-size` token sizes the slot and the glyph of a
directly slotted `ki-icon`, including an icon with an explicit `size`.
The default slot supplies the accessible label. `ki-icon` is hidden from assistive technology
by default; give other slotted media `aria-hidden="true"`.

<Demo
  code={`<ki-button variant="secondary">
  <ki-icon slot="start" name="plus"></ki-icon>
  With slots
</ki-button>
<ki-button variant="primary" disabled>Disabled</ki-button>`}
/>

### Form participation

In momentary mode, `ki-button` defaults to `type="submit"`. It submits the
owning form, runs constraint validation and contributes `name`/`value` to
the form data. Cancel a submission from the form's `submit` event.
Toggle mode takes precedence over `type` and acts independently of form
submission and reset.

<Demo
  layout="block"
  code={`<form onsubmit="event.preventDefault()">
  <ki-button name="intent" value="save">Save draft</ki-button>
</form>`}
/>

### Open a dialog

Set `commandfor` to the ID of a [ki-dialog](/docs/components/dialog/) in the
same document or shadow root. `command="show-modal"` opens it. A configured
dialog command takes precedence over form submission or reset.

<Demo
  code={`<ki-button commandfor="draft-preview" command="show-modal">Preview draft</ki-button>
<ki-dialog id="draft-preview" heading="Draft preview">
  <p>This draft is visible only to you.</p>
  <ki-button slot="footer" commandfor="draft-preview" command="close">Done</ki-button>
</ki-dialog>`}
/>

## Accessibility

The slotted text is the accessible name — icon-only usage is unsupported
(that is [ki-icon-button](/docs/components/icon-button/)'s job, with
its mandatory `label`). `disabled` removes the button from keyboard reach
and exposes the unavailable state through the internal native button; do not
use it for pending or loading semantics. With `href` the internal control is
a native link named by the label, and a disabled link is exposed as an
unavailable link.
