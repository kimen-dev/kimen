## Examples

### In a form

<Demo
  layout="block"

/>

### Initial value

Initial text is declared through the `value` attribute; element text content
is ignored:

<Demo
  layout="block"
  code={`<ki-textarea label="Bio" value="Design systems, gates, and coffee."></ki-textarea>`}
/>

### Appearance and character limits

Set `appearance` to `outlined` for a full border or `filled` for a
tinted surface with a bottom indicator. Both keep the label above the field.
The default appearance follows the theme.

`minlength` uses native minimum-length validation. The textarea keeps edits
past `maxlength` and blocks submission until the value fits. With a maximum,
`show-count` adds the current length to the field description and announces
when the user reaches or exceeds the limit. Use `maxlength-error-text` to
localize the default length error.

<Demo
  layout="block"
  code={`<ki-textarea label="Bio" appearance="outlined" minlength="3" maxlength="24" show-count help-text="Keep it short" value="Designer and front-end developer"></ki-textarea>
<ki-textarea label="Short bio" appearance="filled" maxlength="12" show-count help-text="Keep it short" value="Designs generative interfaces."></ki-textarea>`}
/>

## Accessibility

The `label` prop is the accessible name — mandatory, and `placeholder` is
never a substitute. Enter inserts a line break and never submits the
enclosing form — the inverse of [ki-input](/docs/components/input/).
For single-line values use `ki-input`; rich or formatted editing is out of
scope.
