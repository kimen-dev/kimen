Write it yourself, or let your agent compose it.

The same web components serve both. Hand-written UI imports them directly. Agent-written UI goes through the catalog, which turns a spec into components only after it passes validation.

By hand, in any framework

Standards-first custom elements: identical in plain HTML, React, Vue and Angular, with generated, typed wrappers for the three frameworks.

HTML React Vue Angular 
// pnpm add @kimen/elements @kimen/tokens
import { defineCustomElement } from '@kimen/elements/ki-button';
import '@kimen/tokens/css';

defineCustomElement();

<ki-button variant="primary">Save</ki-button>
 
import { KiButton, KiInput } from '@kimen/react';
import '@kimen/tokens/css';

<KiInput label="Name" onInput={onName} />
<KiButton variant="primary" onClick={save}>Save</KiButton>
 
import { KiButton, KiInput } from '@kimen/vue';
import '@kimen/tokens/css';

<KiInput label="Name" v-model="name" />
<KiButton variant="primary" @click="save">Save</KiButton>
 
import { KiButton, KiInput, TextValueAccessor } from '@kimen/angular';

// standalone component imports: [KiButton, KiInput, TextValueAccessor]
<ki-input label="Name" [formControl]="name"></ki-input>
<ki-button variant="primary" (click)="save()">Save</ki-button>

By agents, through the guarded catalog

Agents emit data, never code. Only catalog components render, only declared actions dispatch, and protocol adapters translate A2UI and MCP Apps into the same path.

Render a spec A2UI MCP server 
import { renderUiSpec } from '@kimen/catalog';

const result = renderUiSpec(spec, {
  surface: document.querySelector('#genui'),
  onAction: (event) => agent.send(event.action),
});
if (!result.ok) console.warn(result.diagnostics);
 
import { createA2uiAdapter } from '@kimen/adapter-a2ui';

const adapter = createA2uiAdapter({
  surface: document.querySelector('#genui'),
  onAction: (event, meta) => channel.send(event, meta),
  onError: (error) => channel.send(error),
});
adapter.apply(message); // A2UI 1.0 or v0.9.1

The guardrail says no, and says why.

validateUiSpec rejects a spec before anything renders, and names the offender and its path so a model can repair it in one round. Select an example to see the recorded validator result.

spec

{ "version": 1,
  "root": { "component": "ki-button",
    "props": { "onclick": "alert(1)" },
    "slots": { "": ["Pay now"] } } }

validateUiSpec(spec)

{ ok: false, issues: [{
    code: 'unknown-prop',
    path: 'root.props.onclick',
    message: 'ki-button declares no prop "onclick"',
    value: 'onclick' }] }

Examples of issue codes: malformed-spec · unknown-component · unknown-prop · invalid-prop-type · unknown-slot · undeclared-action · forbidden-key · size-budget · depth-budget. The validator also rejects getters, functions and shared references.

Capability status

  • Consumer catalog registration: your own components behind a JSON facade, validated and rendered through the same fail-closed guardrail
  • Emitter kit: model-agnostic prompt, catalog-specialized JSON Schema and tool definition so any LLM emits valid specs, with a single-round repair loop
  • Generated framework wrappers: @kimen/react, @kimen/vue and @kimen/angular with typed props, native events and each framework form idiom, drift-gated
  • Schema-constrained guarded renderer: untrusted UI specs render only through the neutral catalog, fail-closed
  • Kimen MCP server: over stdio, agents list and describe the catalog, validate UI specs with correctable issues and render them as MCP Apps surfaces through the guarded renderer
  • Changed-core mutation quality gate in hardening
  • A2UI protocol adapter: declarative A2UI messages render through the guarded renderer
  • MCP Apps adapter: Kimen surfaces reach MCP Apps hosts as self-contained ui:// resources rendered through the guarded renderer
  • AG-UI and json-render protocol adapters planned
  • Neutral runtime component catalog with schema-validated UI specs at the GenUI boundary
  • Machine-readable Web Components foundation with token-driven theming
