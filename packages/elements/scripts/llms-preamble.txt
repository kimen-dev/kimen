Install with `pnpm add @kimen/elements @kimen/tokens`.

Register each component before using it. Every component is exported from
`@kimen/elements/<tag>`, the way `ki-button` is here:

```ts
import { defineCustomElement as defineKiButton } from '@kimen/elements/ki-button';
import '@kimen/tokens/css/core';
import '@kimen/tokens/css/ki-button';
import '@kimen/tokens/css/base';

defineKiButton();
```

Load `@kimen/tokens/css/core` once per page: it is the onmars default theme
without the component tokens. It declares the shared `--ki-*` tokens for
both schemes together with the `color-scheme` they resolve from, so a page
follows its visitor's light or dark preference with no further setup. Then
load one sheet for every `ki-*` tag the page uses, named like its element
import: `@kimen/tokens/css/ki-button` beside `@kimen/elements/ki-button`. A
tag's sheet carries the component tokens that tag needs, including those of
the components it renders, so you add one only for the tags your own markup
writes, slotted ones included. A tag without its sheet paints with undefined
tokens.

The simple alternative is `@kimen/tokens/css` once per page in place of the
core and the tag sheets: every token in one stylesheet. Use it when a page
uses most of the catalog, or renders tags it cannot list in advance, such as
agent-generated UI.

Load `@kimen/tokens/css/base` — the page contract — with either: it paints
the page background, text color and body font from those tokens, declares
no color scheme, and lays out the items of Kimen groups (segments, radios,
options, menu and list items…) one per line until their tags register, so
their labels do not run together.

Human-readable documentation: https://kimen.dev/docs/

## Theming

All themes reassign the same `--ki-*` custom properties, so switching themes
restyles every component with no code changes. Two attributes on the document
root drive selection:

- `data-ki-color-scheme`: `light` or `dark` forces a color scheme for any
  theme, overriding the OS preference. Without it, stylesheets follow
  `prefers-color-scheme`.
- `data-ki-theme`: opts into a non-default theme. Unknown theme names match no
  selector and fall back to onmars through the cascade.

Preference modes, more contrast and reduced transparency, follow
`prefers-contrast: more` and `prefers-reduced-transparency: reduce`, or
`data-ki-contrast="more"` and `data-ki-transparency="reduce"` on the root or
a theme root, and apply over any theme. A theme that wants its own value for
a token under a mode sets its mode token, `--ki-<mode>-<token>` (for example
`--ki-contrast-more-outline-control`), never the token under a media query.

To use the bundled Material 3 reference theme, side-effect import its
stylesheet (exported as `@kimen/tokens/css/material3`) in addition to the
core and tag sheets (or `@kimen/tokens/css`), then select it on the document
root:

```html
<html data-ki-theme="material3" data-ki-color-scheme="dark">
```

## Agent setup

Coding agents can install the Kimen agent skills (`kimen-components` for
pages built with these components, `kimen-genui` for agent-generated UI) and
connect the `kimen-mcp` server, which lists and describes the catalog,
validates UI specs and renders them. Setup for Claude Code, Claude Desktop,
Codex, Antigravity, OpenCode and other clients:
https://kimen.dev/docs/guides/connect-agents/
