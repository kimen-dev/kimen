# ki-dialog

A modal dialog for one interrupting decision or short focused task.

**When to use** — destructive confirmations, blocking choices, and brief
critical input that must be resolved before returning to the page. Always
provide a `heading` and place actions in the `footer` slot. In destructive
confirmations put `autofocus` on the least destructive action.

**When NOT to use** — non-blocking feedback (`ki-alert`, future `ki-toast`),
supplementary hints (`ki-tooltip`), long forms or multi-step flows (navigate
or use a future full-screen variant), menus, or pickers.

## Examples

The `open` attribute reflects the dialog's state. To manage it programmatically,
add `open` or call `show()` to open and remove `open` or call `close()` to dismiss.
When open, the native dialog enters the top layer and the page behind is inert.

```html
<ki-dialog id="session-expired" heading="Session expired">
  Sign in again to continue where you left off.
  <ki-button slot="footer" commandfor="session-expired" command="close" variant="primary">Sign in</ki-button>
</ki-dialog>
```

Low-risk dialogs may opt into backdrop light-dismiss. Boolean presence
semantics apply: `close-on-backdrop="false"` still enables it — omit the
attribute entirely for critical confirmations:

```html
<ki-dialog id="shortcuts" heading="Keyboard shortcuts" close-on-backdrop>
  Press ? anywhere to reopen this reference.
  <ki-button slot="footer" commandfor="shortcuts" command="close">Got it</ki-button>
</ki-dialog>
```

## Recipe: destructive confirmation with `ki-close` reason

Connect a button to a dialog with `commandfor` and the dialog's ID in the
same document or shadow root. `show-modal` opens it, `close` dismisses it,
and `request-close` first gives the dialog a chance to cancel the request.
Opening and closing work through markup once the elements are registered.

```html
<ki-button commandfor="confirm" command="show-modal" tone="danger">Delete account…</ki-button>

<ki-dialog id="confirm" heading="Delete account?">
  This permanently removes your account and all project data.
  <ki-button slot="footer" commandfor="confirm" command="request-close" autofocus>Cancel</ki-button>
  <ki-button slot="footer" commandfor="confirm" command="close" tone="danger" id="confirm-delete">Delete</ki-button>
</ki-dialog>
```

Use `ki-close` to observe the dismissal after focus returns. Its `detail.reason`
is `command` for a close command, `method` for `close()` or `open` removal,
`escape` for the Escape key, or `backdrop` for opt-in backdrop dismissal.
The example adds application logic to remember which footer action was used.

```html
<script type="module">
  const dialog = document.getElementById('confirm');
  let confirmed = false;

  document.getElementById('confirm-delete').addEventListener('click', () => {
    confirmed = true;
  });

  dialog.addEventListener('ki-close', (event) => {
    console.log('closed via', event.detail.reason, '— confirmed:', confirmed);
    confirmed = false;
  });
</script>
```

## Customization

| Token                                        | Controls                          |
| -------------------------------------------- | --------------------------------- |
| `--ki-dialog-max-width`                      | Maximum dialog inline size        |
| `--ki-dialog-bg-image` | Background image layered over the fill. Use `none` for a solid fill. |
| `--ki-dialog-backdrop-blur`                  | Surface backdrop blur             |
| `--ki-dialog-bg`                             | Background fill         |
| `--ki-dialog-radius`                         | Dialog corner radius              |
| `--ki-dialog-backdrop-bg`                    | Backdrop scrim color              |
| `--ki-dialog-shadow`                         | Dialog elevation shadow           |
| `--ki-dialog-heading-font-family`            | Heading typeface                  |
| `--ki-dialog-heading-letter-spacing`         | Heading letter spacing            |
| `--ki-dialog-motion-duration` / `-easing`    | Open/close transition             |

The heading typeface defaults to `--ki-typography-family-heading`, which
themes can set on a theme root to style dialog and alert headings together.
Heading letter spacing defaults to `--ki-typography-letter-spacing-none` (zero
tracking).

Shadow parts: `::part(dialog)` (native dialog surface), `::part(heading)`
(visible h2 title, rendered only when `heading` is non-empty),
`::part(body)` (scrollable body region) and `::part(footer)` (action row,
collapsed when empty).

## Accessibility

- Always provide a `heading` — it is the visible title and the accessible
  name; APG modal dialogs require an accessible name.
- The opener exposes the dialog popup and its expanded state, and focus returns
  to it after close. When using `show()`, call it from the control that should
  regain focus.
- In destructive confirmations, put `autofocus` on the least destructive
  footer action.
- Do not set the internal native `dialog`'s `open` attribute; the host
  attribute is the only public source of truth.
