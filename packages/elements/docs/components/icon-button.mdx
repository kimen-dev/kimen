# ki-icon-button

A token-styled, icon-only action button with native button semantics and a
mandatory accessible name.

**When to use** — a compact, widely understood action where space precludes a
visible label: toolbars, card and dialog corners (close), media transport,
data-row actions. Always supply `label`. Pair with `ki-tooltip` for sighted
discoverability. Use `toggle` for an action such as bookmarking that stays
pressed between activations.

**When NOT to use** — whenever a visible label fits (use `ki-button`),
navigation (use a link), or form submit/reset (use `ki-button`, whose
visible label communicates the consequence).

## Examples

The default slot holds exactly one decorative icon; the accessible name
always comes from the required `label` attribute, never from the slot:

```html
<ki-icon-button label="Close">
  <svg viewBox="0 0 24 24" aria-hidden="true"><path d="M6 6l12 12M18 6L6 18" stroke="currentColor" stroke-width="2" /></svg>
</ki-icon-button>
```

Use filled `primary` for the main action and outlined `secondary` (the default)
for supporting actions. Use `quaternary` for neutral icon actions and `ghost`
for accent icon actions. Use `outline` for an outline at rest and a filled
selected state in toggle mode. `tone` carries intent for momentary actions
in the primary, secondary, quaternary and ghost variants.

```html
<ki-icon-button variant="primary" label="Play">…</ki-icon-button>
<ki-icon-button variant="secondary" label="Copy">…</ki-icon-button>
<ki-icon-button variant="quaternary" label="More options">…</ki-icon-button>
<ki-icon-button variant="ghost" tone="danger" label="Delete row">…</ki-icon-button>
```

`tertiary` is deprecated. Use `secondary` for new icon buttons. Existing
`tertiary` buttons share the `secondary` appearance in onmars and keep
their legacy appearance in Material 3. Development builds warn when
the deprecated variant is used.

Sizes run `xs` (24px, exactly the WCAG 2.2 pointer-target floor) to `xl`
(56px, default `md`); each size pairs a square box with its own icon size:

```html
<ki-icon-button size="xs" label="Clear">…</ki-icon-button>
<ki-icon-button size="xl" variant="primary" label="Record">…</ki-icon-button>
```

## Toggle mode

Set `toggle` to keep the action pressed until the next activation. Set
`selected` to start pressed. The accessible name comes from `label` in both
states. An optional `selected` slot supplies the pressed glyph. An inline
outline SVG whose path inherits its fill takes a `currentColor` fill when
pressed with an empty `selected` slot.

User activation emits `ki-change` with `{ selected }`. Programmatic
updates to `selected` are silent. The radius transition is suppressed when
the person requests reduced motion.

## Recipe: an icon button in a toolbar with a tooltip

`ki-tooltip` supplies the visible affordance and writes the accessible
description; `label` stays the accessible name:

```html
<ki-tooltip label="Closes the dialog">
  <ki-icon-button label="Close">
    <svg viewBox="0 0 24 24" aria-hidden="true"><path d="M6 6l12 12M18 6L6 18" stroke="currentColor" stroke-width="2" /></svg>
  </ki-icon-button>
</ki-tooltip>
```

Inside a native form, activating an icon button never submits or resets the
form: the component is not form-associated. An icon-only submit control is a
when-NOT-to-use — reach for `ki-button`.

## Recipe: close a dialog with an icon button

Give the dialog an ID in the same document or shadow root as the icon button.
`command="close"` dismisses it and focus returns to the opener.

```html
<ki-icon-button slot="footer" label="Close details" commandfor="details" command="close">
  <span aria-hidden="true">✕</span>
</ki-icon-button>
```

## Customization

| Token                                 | Controls                            |
| ------------------------------------- | ----------------------------------- |
| `--ki-icon-button-md-size`            | Square box of the `md` size         |
| `--ki-icon-button-md-icon-size` | Slot box and ki-icon glyph size at `md` |
| `--ki-icon-button-outline-hover-{bg,fg,border}` | Hover palette for outline actions and unselected outline toggles |
| `--ki-icon-button-outline-selected-border` | Selected outline edge |
| `--ki-icon-button-toggle-unselected-hover-overlay` | Hover wash for unselected filled and quiet toggles |
| `--ki-button-primary-neutral-rest-bg` | Primary variant resting background  |
| `--ki-button-md-radius`               | Corner radius of the `md` size      |
| `--ki-button-focus-ring-color`        | Keyboard focus ring color           |

The square box and icon ramp use `--ki-icon-button-{size}-size` and
`--ki-icon-button-{size}-icon-size`. Toggle selection uses
`--ki-icon-button-{variant}-selected-bg`,
`--ki-icon-button-{variant}-selected-fg` and
`--ki-icon-button-toggle-selected-radius`. The fill stays fixed on hover.
The icon-size token takes precedence over an explicit `size` on a
`ki-icon` in the default or `selected` slot.

The original momentary variants use the same visual system as `ki-button`.
This includes the matrix `--ki-button-{variant}-{tone}-{state}-{bg|border|fg}`,
the radius `--ki-button-{size}-radius`, the effect tokens
`--ki-button-{variant}-{state}-shadow`, the per-side bevel
`--ki-button-{variant}-rest-border-bottom` (raised variants only) and the
focus ring. A theme that restyles buttons restyles icon buttons with them.

To style icon buttons apart from buttons, set the button tokens on the
element itself:

```css
ki-icon-button {
  --ki-button-md-radius: var(--ki-radius-round);
}
```

Shadow parts: `::part(button)` (internal native button) and `::part(icon)`
(icon wrapper).

## Accessibility

- `label` is required: it becomes the accessible name of the internal native
  button. An icon button without one exposes no name and fails the
  accessibility audit — the component never invents a fallback.
- The default slot is presentational: slotted content is hidden from
  assistive technology and never contributes to the accessible name. Mark
  raw SVGs `aria-hidden="true"` anyway as belt and braces.
- Native button semantics come from the internal native button: Space and
  Enter activation, visible focus in every theme.
- `disabled` removes the icon button from keyboard reach and exposes the
  unavailable state; do not use it for pending/loading semantics.
- Every size keeps at least the 24×24 pointer target; `xs` sits exactly on
  the WCAG 2.2 floor and no theme may go below it.
- An `aria-description` set on the host (e.g. by a wrapping `ki-tooltip`)
  forwards to the internal button, tracks changes and removal.
