1. Scaffold `ki-prompt-input` from the component generator after the Gherkin pair passes the contract gate.
2. Specify the attachment validator in unit tests and the composer through real-browser S-ID scenarios. Cover pointer density in the isolated browser project.
3. Implement a shadow textarea and mirrored intrinsic layout, native form participation, a labelled list of input chips, and explicit send and stop requests. Use existing icons and the ghost, primary, and secondary button palette. Keep application-supplied tools slotted.
4. Add both theme token sources, localized examples, Storybook stories and a gallery for the shared theme matrix. Register through `component.json` and generate the API, packages and catalog surfaces.
5. Run the locally available gates. The integrator runs the browser matrix, dispatches Linux baselines and sends the shipped commit to the design-system maintainer.
