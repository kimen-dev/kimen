# Implementation Plan: ki-toast and ki-toaster

**Branch**: `claude/objective-cray-c7defd` | **Spec**: [spec.md](./spec.md) | **Issue**: kimen-dev/kimen#353

## Summary

Two Stencil elements in `@kimen/elements`. `ki-toast` renders one flat
surface (tone icon, live region with heading and message, `action` slot,
dismiss `ki-icon-button`) and runs its own timer. `ki-toaster` paints its
`ki-toast` children in the top layer as a manual popover, writes their
`queued` state, exposes a named group and offers `show()` and F6.

## Constitution Check

| Article | How this plan meets it |
|---|---|
| I | Contract in TypeScript + JSDoc; manifests, catalog, llms and wrappers regenerated by the build, never edited. |
| II | `feature.feature` (43 scenarios, five families) precedes the code; every S-ID traced. |
| III | Pure logic (`ki-toast.timing`, `ki-toaster.queue`) TDD in node specs; behavior in Chromium browser tests, red before green. |
| IV | Native popover and top layer; logical properties only; `dismiss-label` and `label` carry the only built-in words; no runtime dependency. |
| V | WCAG 2.2.1 (pause, no auto-dismiss with an action or an error), 4.1.3 (status messages), C27 (DOM order = visual order), focus hand-off, forced colors, reduced motion and transparency. |
| VI | Component tokens alias semantic tokens; the width is a primitive (`ki.size.toast`); `bg-image` and `backdrop-filter` default to `none`; one theme-controlled shadow per list. |
| VII | No exit animation, no countdown, no swipe: what #353 asks for and nothing more. |
| IX | Additive API, declared in `changes/api/049-ki-toast.json`. |

## Risks

- #342 and #347 landed while this was built: the heading family is linked;
  the toast keeps its own whole backdrop filter, `none`, because it is flat.
- The toaster is a group, not a landmark, so axe's best-practice `region`
  rule asks pages to keep it inside one of their landmarks.
