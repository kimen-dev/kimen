## What this is

Kimen is an open-source, AI-First generative UI library: StencilJS web
components (`ki-` prefix), a neutral schema-constrained catalog, and disposable
protocol adapters (A2UI and MCP Apps today; AG-UI and json-render planned).
One-person, AI-First operation: agents implement, deterministic gates verify,
and a single founder merges.

## Law of the repo

1. **The constitution digest governs everything.** Read
   `.specify/memory/constitution.md` before working: it is the operative
   governance text of this repository (11 articles, workflow, human gates).
   On conflict, escalate to the founder.
2. **Use specs proportionately** (Art. II). A concise Gherkin contract is
   required for public component behavior/API, new interaction patterns and
   guardrail/security boundaries. Bug fixes need a failing regression test.
   Internal refactors, tooling, dependencies and docs do not need Spec Kit.
   Plans/checklists/tasks are optional tools for genuinely complex changes.
3. **One fast quality result defines ordinary PR readiness** (Art. III/X).
   Run `bash scripts/gates/gates-suite.sh`. Mutation runs once daily, packaging
   and three-browser verification run at release, and path-specific controls
   run only when their surface changes.
4. **Never hand-edit generated artifacts** (Art. I): manifests, catalog,
   llms.txt, wrappers and this file (once generated) are regenerated, not
   patched. `pnpm regen` rebuilds the token stylesheets and reference, the
   elements manifests, API snapshot, wrappers and agent docs, and the catalog.
   The generated-sync gates verify their outputs.
5. **Tokens only** (Art. VI): no hardcoded visual values, CSS logical
   properties only, no hardcoded user-visible strings.
6. **Containment** (Art. XI): unattended loops run sandboxed (`sandbox/`),
   least-privilege, no publishing credentials, no permission-bypass outside
   credential-free sandboxes.

## Conventions

- Once per clone, run `bash scripts/dev/setup-merge-drivers.sh`. From your
  feature branch, merge `origin/main` with `git merge --no-ff --no-commit
  origin/main`. The driver selects incoming main's generated bytes for file
  content conflicts. Resolve source conflicts normally and select main's
  version for any generated add/delete conflicts where Git needs a choice.
  Then run `pnpm regen`, stage the regenerated outputs and commit the merge.
- Components: `<ki-name>` tags, scaffolded via Nx generators, never by hand.
- Clean-context review is optional, advisory and one-pass for high-risk or
  unfamiliar changes; it never creates a required Check Run.
- Commits: conventional commits; external contributions carry DCO sign-off.
- Status: pre-v1, factory phase. See `/docs/roadmap.md`.

## Adding a component

1. Write and lint the Gherkin contract. Run `pnpm component:new ki-name --spec NNN-ki-name` to scaffold from it.
2. Work in `packages/elements/src/components/ki-name/` and the two component token files under `packages/tokens/tokens/component/`. Replace the TODOs and map the real-browser tests to the approved S-IDs. Add pure-logic unit coverage when the component has a helper.
3. Complete the states in `gallery.ts`, the stories, `docs/site.mdx`, `docs/storybook.mdx` and `usage/examples.md`. The visual suite collects galleries from component folders. The CI visual-baselines workflow produces the Linux references.
4. Set bare-page and pointer expectations in `component.json`. Direct imports, wrappers and docs discover the tag. Agent catalog inclusion requires a separate reviewed opt-in (Art. VIII).
5. Keep a component within its individual budget. Add a reviewed marginal `sizeBudget` entry only when its emitted artifacts need more headroom. Declare `budgetGroup.members` for a composite measured together. See `scripts/lib/bundle-size-budget.mjs` for the re-base rule.
6. Run `pnpm regen`, declare any public API additions with `pnpm api:declare`, and run `bash scripts/gates/gates-suite.sh`.
